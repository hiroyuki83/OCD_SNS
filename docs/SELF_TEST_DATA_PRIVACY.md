# 心理セルフチェックデータのプライバシー要件

最終更新: 2026-09-28
対象: Y-BOCS / IES-R / ITQ / LSAS の保存結果

## 基本方針

心理セルフチェックの回答・得点・結果ラベルは、通常のSNS投稿やプロフィールよりセンシティブな情報として扱う。

CoCo のアプリケーション上では、保存結果は原則として **回答した本人だけが閲覧できるデータ** とする。

## アクセス制御

- 保存時は必ず認証済みユーザー本人の userId に紐付ける。
- 結果履歴の取得は、認証セッションから解決した本人の userId で絞り込む。
- 他ユーザーの公開プロフィールには表示しない。
- 投稿・検索・フィード・通知へ結果を流さない。
- ADMIN / MODERATOR の通常の管理画面には結果・回答・得点を表示しない。
- モデレーション画面、通報画面、Audit Log、管理メモへ結果を自動転記しない。
- メール本文へ結果・回答・得点を自動送信しない。

## 管理者とインフラ

ADMIN / MODERATOR というアプリ内ロールに、心理セルフチェック結果を閲覧する権限を付与しない。

ただし、データベース運用権限を持つインフラ管理者がDBへ直接アクセスできる可能性は、アプリ内権限とは別問題である。Production DB のアクセス権は必要最小限にし、接続情報をコードやログへ残さない。

## ログ

以下をアプリケーションログへ出力しない。

- 設問ごとの回答
- 症状リスト
- ITQ の結果詳細
- 合計点・下位尺度得点とユーザー識別情報の組み合わせ

保存失敗時は、例外の内容にユーザー入力が含まれないよう注意する。

## 将来のアカウント削除・エクスポート

ユーザー向けデータエクスポートを実装する際は、本人確認後に本人のセルフチェック結果を含められるようにする。

アカウント削除を実装する際は、セルフチェック結果も削除対象に含める。バックアップからの自然消滅期間は、別途バックアップ保持ポリシーで明示する。

## 分析利用

現時点では、心理セルフチェック結果を広告、ユーザー推薦、モデレーション判定、アカウント評価には利用しない。

将来、集計・研究・サービス改善へ利用する場合は、この要件定義とは別に利用目的、集計単位、匿名化または仮名化、同意の扱いを決めてから実装する。

## 回帰防止

CI で以下を検査する。

- admin / moderation のソースから self-test Prisma models を直接参照していないこと。
- 公開プロフィール / 公開 user API から self-test Prisma models を直接参照していないこと。
- 本人の心理検査ページでは各結果取得時に userId 条件があること。
